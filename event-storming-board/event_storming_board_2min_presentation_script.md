# Event Storming Board — ポスター説明台本

**目的:** ドメインエキスパートの見識をクラウドネイティブなプラットフォーム設計に活かす意義と、Event Storming Board の特徴を伝える  
**想定説明時間:** 約2分

## 1. ポスター説明台本（約2分）

### 0:00〜0:20｜Event Storming とは？

*【ポスター上部を指す】*

> このツールの目的は、業務に詳しい人の知識を、クラウドのプラットフォーム設計に活かすことです。
>
> Event Storming とは、業務担当者とエンジニアが、業務で起きた出来事を付箋に書き、時間順に並べながら、業務の仕組みや課題を一緒に理解する手法です。

### 0:20〜0:40｜従来のツールとの違い

*【ポスターの凡例を指す】*

> Mural などのホワイトボードや、FigJam、Miro のテンプレートでも実施できます。
>
> Event Storming Board の特徴は、色付きの付箋に加えて、**意味を持つアイコンを採用したこと**です。単なる図ではなく、業務要素とその関係性を構造化できます。

### 0:40〜1:10｜矢印なしの全体図

*【1枚目の図を指す】*

> これは、ECサイトで注文を受けてから発送するまでの業務です。
>
> オレンジは「注文が作成された」などの出来事、青は「決済を要求する」などの指示、緑は画面で参照する情報です。
>
> ここでは、業務の全体像を把握することを重視し、矢印を表示せず、付箋とアイコンだけで表現しています。

### 1:10〜1:45｜アイコンと関係矢印

*【2枚目の図を指す】*

> 次に、矢印を表示した状態です。
>
> 建物のアイコンは業務の整合性を守るアグリゲート、歯車は出来事に応じた処理を決めるポリシー、アンテナは外部システムを表します。
>
> 例えば、決済失敗という出来事から注文キャンセルという指示への関係を表現できます。
>
> 矢印は必要なときだけ表示でき、ズームやドラッグ操作で、全体像と詳細を切り替えながら検討できます。

### 1:45〜2:00｜クラウド設計への展開

*【ポスター下部を指す】*

> このボードは、付箋だけの試作から、アイコンと関係性を表現するツールへ進化してきました。
>
> 結果をJSONで保存し、AIによる分析やサーバーレス設計の検討に活用できます。
>
> **目指すのは、イベントから設計を導くことです。**

## 3. 説明担当者が理解しておくべき4つのポイント

| キーワード | 説明できれば十分な内容 |
|---|---|
| **ドメイン** | ECサイトの注文業務など、システムが扱う業務領域 |
| **ドメインイベント** | 「注文が作成された」など、業務ですでに起きた出来事 |
| **アイコン型の価値** | Aggregate・Policy・External System の役割と入出力の関係を表現できる |
| **JSONの価値** | モデルを画像だけで終わらせず、AI分析や後続の設計に再利用できる |

## 4. 説明時の注意事項

- **「このツールが自動的にAWSのシステムを設計する」と説明しないこと。** 現時点での価値は、ドメインエキスパートの見識を構造化し、AIによる分析や設計判断に利用しやすくすることです。
- MiroやFigJamにも拡張機能があります。既存ツールを否定せず、**Event Storming 固有の業務要素に意味と接続ルールを持たせた設計**を強調してください。
- 「矢印なし」は業務の全体像を把握するため、「矢印あり」は業務要素の関係性を確認するため、と説明すると伝わりやすくなります。

## 5. 最後に伝える一文

> **付箋による業務の見える化から、アイコンによる関係性の構造化へ。クラウドネイティブなプラットフォーム設計への展開を加速します。**
